# Repository interface

domain が所有し、data が実装する。これで依存が内向きに反転する。

## 確認する対象

- `domain/repository/SampleRepository` の現在のシグネチャ
- 実装している `data/repository/InMemorySampleRepository`
- 呼び出している UseCase

## 実装時の注意

- インタフェースは domain に置く。data 側に置くと依存の向きが崩れる。
- 戻り値に data 層の型を出さない。`SampleDefinition` は data の都合であり、
  ここに現れてはならない。
- ストリームを返すメソッドは cold な `Observable` を返す契約とする。
  購読するまで何も起きず、Scheduler も指定しない。
- 同期で返せるもの（一覧、1 件取得）を無理にストリームにしない。
  サンプル定義は静的なので、`List` と `Sample` をそのまま返す。
- 存在しない識別子は例外にする。画面遷移は自前の識別子でしか起きないため、
  これは回復対象ではなく実装の誤りである。

## テスト判断

- インタフェース自体はテストしない。実装側でテストする。
- 契約を変えたときは、既存実装とすべての呼び出し側を確認する。

## 検証観点

- data 層の型やアノテーションが署名に漏れていないか。
- ストリームを返すメソッドが cold である前提を、実装側が守れているか。
