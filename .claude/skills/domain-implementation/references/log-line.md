# SampleLogLine

サンプルの実行過程を 1 行として表す。このアプリの観察対象そのもの。

## 確認する対象

- `domain/model/SampleLogLine` の生成経路
- 生成しているすべての箇所（`data/catalog/SampleLogs` と各サンプル本体）
- 整形している箇所（`presentation/run/SampleRunViewModel`）

## 実装時の注意

- スレッド名は生成時に `Thread.currentThread().getName()` で確定させる。
  生成が値の放出と同じスレッドで起きるため、これで自然に正しくなる。
- 生成経路を `onCurrentThread(String)` 1 つに保つ。スレッド名を外から渡せるようにしない。
  渡せるようにした瞬間、どこで確定させるかを呼び出し側が毎回考えることになり、
  間違えると全行が `main` になる。
- 表示形式（`[スレッド名] メッセージ` の組み立て）を持たせない。整形は presentation の仕事。
- 値の追加（発生時刻、イベント種別など）を検討するときは、
  それが観察に必要か、presentation で導けないかを先に確認する。

## テスト判断

- 生成したスレッドの名前が入ることを JVM Unit Test で押さえる。
- 別スレッドから生成した行のスレッド名が呼び出し元と一致することを確認する。

## 検証観点

- メッセージ文字列にスレッド名を手で埋め込んでいる箇所がないか（二重になる）。
- 生成後にスレッドをまたいでから名前を決めている経路がないか。
